# KASA (KASA)

نرم‌افزار موبایل‌محور حسابداری، فروش و مدیریت موجودی.

## وضعیت فعلی
نسخه 0.1.0 — پوسته اولیه داشبورد RTL و موبایل‌فرست.

## مسیر توسعه
- داشبورد مالی
- فروش و فاکتور
- خرید
- موجودی و گردش کالا
- اشخاص و حساب‌ها
- دریافت و پرداخت
- هزینه‌ها
- گزارش‌های بازه‌ای
- پشتیبان‌گیری و بازیابی
- آماده‌سازی PWA و سپس بسته‌بندی موبایل

## اصول داده
- ثبت تراکنش‌ها باید قابل ردیابی باشد.
- موجودی از روی گردش‌های ثبت‌شده محاسبه شود.
- مبلغ‌ها با دقت عددی مناسب حسابداری نگهداری شوند.
- تاریخ شمسی در رابط کاربری پشتیبانی شود.
- ساختار برای حالت آفلاین‌اول طراحی شود.

این پروژه مستقل از پروژه PsychGame است.

## اشتراک ماهانه

ساختار اشتراک KASA به‌صورت **server-verified** طراحی شده است؛ یعنی اپلیکیشن به‌تنهایی حق فعال‌کردن اشتراک را ندارد.

### کانال‌های پرداخت

- **نسخه وب/PWA:** درگاه مستقیم از طریق سرور.
- **نسخه کافه‌بازار:** خرید درون‌برنامه‌ای بازار در لایه Android، سپس ارسال purchase token به سرور KASA برای تأیید.
- **نسخه مایکت:** خرید درون‌برنامه‌ای مایکت در لایه Android، سپس ارسال purchase token به سرور برای تأیید.

هر سه مسیر به یک اشتراک ماهانه و یک حساب کاربری متصل می‌شوند.

### قرارداد بک‌اند

- `POST /subscription/checkout` برای پرداخت وب.
- `POST /subscription/store/verify` برای تأیید خرید بازار/مایکت.
- `GET /subscription/status` برای دریافت وضعیت اشتراک.
- سرور باید کاربر، پلن، مبلغ و تاریخ انقضا را تعیین کند.
- توکن خرید فروشگاه باید در سرور با سرویس همان فروشگاه بررسی شود.
- فقط پس از تأیید معتبر، entitlement اشتراک فعال می‌شود.
- درخواست‌های تکراری باید idempotent باشند تا یک خرید دوبار ثبت نشود.
- کلیدها و اسرار بازار، مایکت و درگاه هرگز نباید داخل JavaScript فرانت‌اند قرار بگیرند.

### نکته فنی نسخه بازار

هسته فعلی KASA با Vite/TypeScript ساخته شده است. برای نسخه بازار، رابط Android باید یک لایه Native برای SDK پرداخت بازار داشته باشد. این لایه خرید را انجام می‌دهد و نتیجه معتبر خرید را برای `verifyStorePurchase()` به سرور می‌فرستد. بنابراین بعداً با تغییر کانال انتشار، هسته حسابداری دوباره نوشته نمی‌شود.

درگاه واقعی تا زمان اتصال بک‌اند و حساب توسعه‌دهنده، عمداً شبیه‌سازی نمی‌شود.
